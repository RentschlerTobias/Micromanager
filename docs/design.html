Design state of 2026-10-04 (including local vs cloud routing, censorship guards, decision backends and overrides); nothing here is implemented yet beyond permissions (N13) and model routing.

One Jev call, many classifications

Yes. One request carries a map of questions, mixed types allowed (choice, score, noul). TypeSafe answers them "in parallel and in isolation against the same state in one go"; adding questions barely changes latency, and only input tokens are billed, so the shared state is paid once. src/jev.ts already sends questions: Record<id, Question>, and src/decide.ts asks 3–4 questions per call today.

Multi-select = one noul per option

There is no multi-label type. A choice picks exactly one. For skills, tool groups and needs, each option gets its own noul ("this task needs symbol navigation"); code keeps every option above its floor, capped (at most 3 skills).

Isolated answers: dependencies live in code

Questions in one call cannot see each other's answers. So a call asks only independent facts, and code combines them: the model comes from role × needs (chooseModel), the pipeline from the N5 answers by rules. When a decision truly depends on another answer, it is a second call (~100 ms).

Consistency check

Because answers are isolated, they can contradict (role explore but needs.shell high). Code checks the combination against the role matrix; the role matrix always wins, and a clash lowers the effective confidence, which can send the decision to the user.

Who gets which skills and tools

The role matrix (src/roles.ts) is the upper bound. Jev's profile (N5b) can only switch things off inside it, never on beyond it. "Always" items are set by rule, without Jev.
